### Maintainability & Technical Debt

**Purpose**: Identify maintainability issues, quantify technical debt, and provide refactoring recommendations.

**Key Areas**:
- Code complexity analysis (cyclomatic complexity, cognitive complexity)
- Dependency management and coupling analysis
- Code duplication detection
- Test coverage and quality assessment
- Refactoring strategies and technical debt quantification
- Static analysis and code smells identification

**When to Use**: Technical debt assessments, code quality reviews, refactoring planning, long-term maintainability evaluation
